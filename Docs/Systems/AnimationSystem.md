# Направления и Animator игрока

## Назначение и состояние

В существующем PlayerController/Player.controller подготовлен выбор восьми направлений. Это **техническая основа**, не восемь готовых художественных циклов. Исходный myproject1idle.ase имеет один кадр/ракурс64×64. Пробная генерация built-in image_gen по этому исходнику дала1983×793 вместо запрошенного листа256×64 и изменила детали дизайна; результат отклонён и не подключён к проекту. Программное уменьшение/сдвиги одного кадра не используются как замена настоящей ходьбы.

## Компоненты и последовательность

PlayerController читает прежний Input System, нормализует WASD/стрелки и сохраняет последний ненулевой вектор. Animator bool `isMoving` сохранён для совместимости; добавлены Float MoveX/MoveY/LastMoveX/LastMoveY. В исходном controller добавлены Player_DirectionalIdle/Walk и два SimpleDirectional2D Blend Tree с восемью точками, диагонали нормализованы. Idle читает LastMove*, Walk читает Move*. Переходы без Exit Time и задержки. Прежние три состояния/клипы сохраняются, но недостижимы из нового default Idle. Any State/Entry переходы к старым состояниям не добавлены.

OnDisable сбрасывает ввод/скорость; WorldInputGate останавливает движение и оставляет последнее направление. FlipX directional-графикой не используется, чтобы не искажать будущие отдельные ракурсы. Rigidbody2D/коллайдеры/камера сохраняются. BattleScene продолжает показывать тот же исходный Sprite через BattleUnit, отдельного героя не создаётся.

## Данные и настройка

`Assets/Animations/Player64` содержит16 клипов: Walk/Idle × Up,Down,Right,Left,UpRight,UpLeft,DownRight,DownLeft. Пока каждый использует один исходный Sprite без Transform-кривых, как временный single-angle fallback. Это16 именованных мест для кадров, а не16 уникальных анимаций. Последнее направление сохраняется **логически**; видимая ориентация появится только с соответствующими изображениями.

Чтобы подключить настоящую графику: открыть соответствующий клип в Animation, заменить Sprite-ключи кадрами нужного направления, поставить8FPS/Loop Time; для4 кадров использовать времена0/.125/.25/.375 и повтор первого на.5 для замыкания. Все кадры native64×64, единая pixel grid/feet baseline/PPU100/pivot, Point/no mipmaps/no compression. Не анимировать Transform Player: им владеет физика. Исходный myproject1idle не перерисовывать и не заменять другим дизайном.

## Какие изображения ещё нужны

Для полной ходьбы — восемь циклов Walk_Up/Down/Right/Left/UpRight/UpLeft/DownRight/DownLeft, по4–8 **разных** кадров64×64 (32–64 кадров суммарно). Для визуального последнего взгляда — семь отсутствующих Idle-ракурсов и подтверждение, какому направлению соответствует оригинальная фронтальная поза; можно по одному кадру, затем2–4 для дыхания. Диагонали имеют собственный вид одежды/лица/оружия. Подходят PNG отдельными кадрами/ровный sprite sheet либо Aseprite с direction-тегами; никаких увеличенных псевдо64 изображений.

## Проверки и расширение

Новый сценарий PlayerDirectionFlowTests проверяет синтетические клавиши, восемь нормализованных векторов, выбор Idle/Walk, параметры последнего направления и gate. Регрессионные сценарии отдельно проверяют физическую встречу, команды и возврат. Полная художественная анимация/нет дрожания/верный разворот пока не заявляются; качество необходимо проверить вручную после подключения настоящих кадров. [Поэтапный отчёт](../PlayerRework.md), [PlayerController](../Scripts/PlayerController.md).

Рост скорости от AGI, классы и прочие RPG attributes пока не подключены этой подготовкой Animator. Другие визуальные системы: [EnemyVisuals](EnemyVisuals.md), [BattleAnimationSystem](BattleAnimationSystem.md).
