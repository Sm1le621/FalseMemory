# Расходуемые предметы

## 1. Назначение

Этап4.1: общий InventoryState30 слотов на прежнем BattleInventory Player; используется миром/боем, без копии. ItemData хранит определения, Gold отдельный единственный баланс.

## 2. Общая логика

Количество хранится на Player, определение/эффект в SO. Count/TryConsume делегируются State. Начальный items переносится лениво один раз; его дальнейшая правка не меняет runtime запас. CanAdd/TryAdd атомарны, добавление не частичное. State поддерживает перенос/обмен/слияние/деление и Changed.

## 3. Основные компоненты

BattleInventory, BattleItemStack, BattleConsumable, Abilities, Manager/UI.

## 4. Взаимодействие скриптов

Unit.Inventory ищет компонент; Manager строит Items, Abilities проверяет количество/цель и вызывает Health.Heal.

## 5. Последовательность событий

Items → название/Count → выбор → TryConsume → до 30 HP/зелёный текст → следующий ход. При 0 недоступен; возврат без расхода.

## 6. Настраиваемые параметры

Potion.asset: Self, healing30, зелёный. Player.Inventory.items: Potion×3; count≥0.

## 7. Использование в Unity

На Player назначить BattleInventory.items[].definition и Count. Во время Play после урона выбрать Items/Potion. Количество после возврата остаётся уменьшенным.

## 8. Расширение

Для Hi-Potion создать новый лечебный SO и стопку. Ether/воскрешение/статусы потребуют нового типа эффекта/обработчика; интеграция с будущим мировым инвентарём отдельно.

## 9. Ограничения и проверки

Нет UI инвентаря мира, оружия/брони/квестовых предметов. Полное HP не запрещает расход. Сохранение только в живых объектах текущей сессии. Ноль/двойное применение/стопки проверены тестами.
