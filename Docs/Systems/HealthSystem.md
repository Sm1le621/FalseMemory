# Здоровье и HUD

5.1: SetMaximumHealth(maximum) нормализует max≥1, сохраняет/ограничивает currentHP и обновляет существующие Slider/TMP. BattleUnit передаёт стартовый maxHP+growth; здоровье/GUI не дублируются. Level Up не является Heal и не воскрешает. [ProgressionSystem](ProgressionSystem.md).

## 1. Назначение

Один Health хранит HP в мире и бою.

## 2. Общая логика

Start инициализирует HP; урон ограничивает 0…maxHealth, лечение не воскрешает и не превышает максимум. Ссылки UI необязательны.

## 3. Основные компоненты

Health, BattleUnit, BattleAbilities, BattleUI; мировой Slider и HPText.

## 4. Взаимодействие скриптов

Unit.Health возвращает исходный компонент; Manager/Abilities применяют изменения; Health обновляет мировой HUD, UI читает те же HP для боя.

## 5. Последовательность событий

Первый Start → полный HP → урон/лечение → UpdateUI → бой заканчивается при HP0. Возвращение не вызывает Start снова.

## 6. Настраиваемые параметры

Player100, Enemy60 maxHealth; hpSlider/hpText у игрока назначены. Slider не интерактивен; UI должен иметь верхние левые якоря/отступы и CanvasScaler.

## 7. Использование в Unity

На Player проверить Health, ссылки HUD и неинтерактивность Slider. Для проверки лечения в Play получить урон, затем Heal/Potion. Battle UI получает данные через Unit.

## 8. Расширение

Будущее отделение HUD потребует событий/наблюдателя и обновления вызывающего кода; пока это не сделано. Новые лечения должны использовать Health.Heal, не отдельное HP.

## 9. Ограничения и проверки

Health всё ещё связан с UI; прямое изменение currentHealth не обновляет HUD. Отрицательный TakeDamage лечит. Лимиты/единый объект/обновление HUD после победы покрыты тестами.
