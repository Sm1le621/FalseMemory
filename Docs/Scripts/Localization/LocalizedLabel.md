# LocalizedLabel

## 1. Название и назначение

Исходник: F:/LLM/UUU/Miri/FalseMemory/Assets/Scripts/Localization/LocalizedLabel.cs.

Связывает статическую TMP-подпись с одним ключом GameText и обновляет её при смене языка.

## 2. Как работает

На старом UI сохраняется TMP-компонент и оформление. При включении/Bind назначенный ключ читается; на отключении подписка снимается.

## 3. Методы и функции

`Awake()` кеширует TMP_Text того же объекта. `OnEnable()` подписывает Refresh на LanguageChanged и обновляет; `OnDisable()` отписывает. `Refresh()` void получает компонент при необходимости, непустой key → Get; пустой ключ оставляет прежний текст. `Bind(text,key)` static void находит/добавляет ровно один LocalizedLabel, назначает key, вызывает Refresh. Callbacks не меняют события игровых кнопок.

## 4. Переменные и Inspector

key string — стабильный ключ; private label TMP_Text. DisallowMultipleComponent и RequireComponent TMP_Text. На сцене назначены title/controls/actions/разделы инвентаря; MainMenuBootstrap связывает создаваемые подписи.

## 5. Связи

GameText.LanguageChanged/Get, TextMeshProUGUI/TMP_Text. Динамические HP/MP/EXP/сообщения формируют игровые контроллеры, данный компонент туда не добавляется.

## 6. Пример

Use-кнопка хранит inventory.use. При включении её прежняя подпись меняется на Use; onClick остаётся WorldItemUseController.

## 7. Настройка в Unity

Добавлять на объект с TMP_Text и указать key, либо вызвать Bind при создании UI. Ссылки SampleScene сохранены MCP. Компонент не ExecuteAlways: вне Play редакторный текст сохраняется отдельной MCP-настройкой.

## 8. Возможные проблемы

Неверный ключ даёт диагностический [key]; пустой не обновляется. Не связывать статическим ключом поле, которое управляется динамическим контроллером — иначе возможна перезапись сообщения. Для будущих языков нужно проверить шрифт и ширину.
