# BattleInventory

## 1. Название и назначение

Исходник: `Assets/Scripts/Battle/BattleInventory.cs`.

Хранилище предметов на объекте Player. Содержит стартовые записи из сцены, лениво создаёт `InventoryState` на 30 слотов и предоставляет удобные методы количества/списания/добавления. Компонент живёт на том же объекте, что `BattleUnit`, `Health` и `InventoryWindow`, поэтому инвентарь сохраняется при переходе в бой и обратно.

## 2. Как работает

При первом обращении к `State` компонент создаёт `InventoryState` и добавляет сначала записи `items` (старый формат `BattleItemStack`), затем `startingItems`. Если стартовые предметы не помещаются в 30 слотов, выбрасывается `InvalidOperationException`. Полученное состояние кешируется до конца жизни объекта; скрытие/показ окна и переход в бой его не сбрасывают.

`Definitions` объединяет все определения из состояния и стартовые записи, убирая дубликаты. `Count` считает количество по `ItemData`, `TryConsume` списывает одну единицу, `TryAdd` добавляет предмет, `Summary` формирует строку для HUD.

## 3. Методы и функции

- `State` → `InventoryState`; ленивая инициализация из `items` и `startingItems`, проверка вместимости.
- `Definitions` → `IEnumerable<BattleConsumable>`; уникальные расходуемые определения для меню/тестов.
- `Count(ItemData definition)` → `int`; текущее количество в слотах.
- `TryConsume(BattleConsumable definition)` → `bool`; удаляет одну единицу.
- `TryAdd(ItemData definition, int amount)` → `bool`; добавляет предмет с учётом стаков.
- `Summary` → `string`; строка вида `Potion x3  Iron Sword x1`.

## 4. Переменные и Inspector

- `items` — список `BattleItemStack` (`definition`, `count`); сохранён для совместимости со сценой.
- `startingItems` — список `StartingItem` (`definition`, `count`), удобный для новых сцен.
- `state` — `[NonSerialized]`, внутренний кеш `InventoryState`.

Стартовые значения в `SampleScene`: Iron Sword ×1, Leather Armor ×1, Potion ×3. Пустые записи и `count ≤ 0` игнорируются.

## 5. Связи

Требуется для `InventoryWindow`, `EquipmentController`, `BattleAbilities`, `WorldItemUseController` и `BattleHUD`. `InventoryState` владеет слотами, золотом, экипировкой и событиями. `ItemData`/`BattleConsumable` — определения предметов. При переходе в бой используется тот же компонент, поэтому отдельный боевой инвентарь не нужен.

## 6. Пример

В сцене заданы Potion ×3. После использования одного зелья `TryConsume` уменьшает количество до 2, `Summary` показывает `Potion x2`, а окно инвентаря обновляется через событие `InventoryState.Changed`.

## 7. Настройка в Unity

Компонент находится на Player. Заполни `items` или `startingItems` в Inspector; не создавай второй инвентарь в `BattleScene`. Для нового предмета создай ассет `ItemData`/`BattleConsumable` и добавь ссылку в стартовые записи. Вместимость фиксирована — 30 слотов.

## 8. Возможные проблемы

Если стартовые предметы не помещаются, при первом обращении к `State` будет исключение. Изменение списков после создания `State` не влияет на уже созданное состояние. Нет сохранения на диск: после перезапуска игры инвентарь снова стартовый. `Definitions` показывает только расходуемые предметы, хотя в слотах могут быть оружие и броня.
