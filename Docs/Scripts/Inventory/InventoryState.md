# InventoryState

## 1. Название и назначение

Исходник: `Assets/Scripts/Inventory/InventoryState.cs`.

Сериализуемая модель 30 слотов. `InventorySlot` — внешне неизменяемая пара `ItemData`/количество. Отдельного баланса золота нет.

## 2. Как работает

Каждая операция сначала проверяет весь запрос, затем меняет слоты и только после успеха отправляет `Changed`. Отказ не оставляет частичного добавления, удаления или переноса. UI читает модель через `GetSlot`, но не хранит собственный запас.

## 3. Методы и функции

- `Definitions` — уникальные занятые определения в порядке слотов.
- `IsEmpty` — true, если все слоты пусты (используется тестами и проверками).
- `GetSlot(int index)` — readonly `InventorySlot`; неверный индекс бросает `ArgumentOutOfRangeException`, пустой слот возвращает общий `Empty`.
- `Count(ItemData item)` — суммарное количество с насыщением `int.MaxValue`.
- `CanAdd(ItemData item, int amount)` — проверяет null, положительное количество, конфликт стабильного `id` и суммарное свободное место с учётом `StackLimit`.
- `TryAdd(ItemData item, int amount)` — сначала дополняет существующие стопки, затем занимает пустые слоты.
- `TryRemove(ItemData item, int amount)` — проверяет общий запас, списывает по стопкам и освобождает обнулённые слоты.
- `TryMoveOrMerge(int from, int to)` — переносит/обменивает разные предметы; одинаковые стакаемые предметы сливает до лимита. Полная одинаковая цель отклоняется, остаток остаётся у источника.
- `TryExchangeSingle(int index, ItemData expected, ItemData replacement)` — internal-операция для экипировки: меняет один ожидаемый предмет на один нестакаемый предмет без конфликта ID.
- `Conflicts(ItemData item)` / `Valid(int index)` — private проверки ID и диапазона `0..29`.

Unity-методов жизненного цикла нет.

## 4. Переменные и Inspector

- `Capacity = 30`.
- `slots` — private `InventorySlot[30]`.
- `Changed` — событие после успешной операции.
- `Empty` — статический пустой слот; в массив не записывается.

Класс не является компонентом; приватные поля не редактируются через Inspector.

## 5. Связи

Владелец — `BattleInventory.State`. `InventoryWindow` отображает слоты, `WorldItemUseController` расходует расходники, `EquipmentState` обменивает предметы, `BattleUnit` читает экипировку. Подписчики `Changed` не должны рекурсивно менять инвентарь.

## 6. Пример

299 Potion с лимитом 10 занимают 29 полных стопок и одну из 9 штук. Добавление 2 отклоняется целиком, добавление 1 доводит запас до 300. Перетаскивание 10 предметов на стопку с 3 при лимите 10 переносит 7, оставляя 3 у источника.

## 7. Настройка в Unity

Не компонент. Создаётся в `BattleInventory` при первом обращении к `State`. Стартовые предметы задаются в `startingItems`; приватные слоты не редактируются напрямую.

## 8. Ограничения и расширение

Нет дискового сохранения, торговли, разделения стопки и квестовых предметов. `Count` насыщается `int.MaxValue`; уменьшение `maxStack` ниже текущего количества требует отдельной миграции. Изменение ID у существующего ассета может создать конфликт с уже лежащим предметом.
