# Git в FalseMemory простыми словами

Git хранит версии файлов. **Коммит** — локальная записанная версия. **Push** — отправка уже существующих коммитов в удалённый репозиторий. Несохранённые коммитом файлы push не отправляет. Это касается и новых скриптов с `.meta`.

## Обычная задача

1. Прочитай [AGENTS.md](../../AGENTS.md), проверь git status, текущую ветку, индекс и существующие изменения. Чужие или незавершённые файлы сохраняются.
2. Изучи код/Unity/Docs, выполни необходимые изменения и подходящие проверки.
3. Обнови документы затронутых скриптов/систем, указатель, архитектуру и Changelog по факту изменения.
4. Проверь git diff. Добавь только относящиеся к задаче пути через git add. Если в индексе уже есть чужие файлы, не включай их в свой коммит.
5. Проверь git diff --cached, затем создай непустой локальный commit Conventional Commits: feat/fix/refactor/docs/test/chore по смыслу результата.
6. Сообщи ветку, hash, сообщение и количество файлов. Без отдельной команды владельца остановись на локальном коммите.

Реализация и её документация входят в один логический коммит. Новые большие задания сохраняют проверенные подэтапы отдельно. Уже реализованные совместно изменения не нужно искусственно откатывать ради выдуманной истории последовательных коммитов.

## Что сохранять

Assets с нужными `.meta`, Packages, ProjectSettings, Docs и AGENTS. `.meta` содержит идентификаторы, сохраняющие ссылки Unity. Library/Temp/Obj/Logs/Builds/.vs и кеши не добавляются. Текущий `.gitignore` уже подходит. Новое правило исключения не является разрешением удалить ранее отслеживаемые файлы.

Не сохраняй пароли/токены/API-ключи. Если имя/почта автора Git не настроены, сообщи владельцу; не придумывай его данные. Локальный git init разрешён при отсутствии репозитория, удалённый репозиторий — только по разрешению.

## Когда владелец говорит «Сделай git push»

Проверь ветку, remote, исходящие коммиты и их файлы, затем обычный push в однозначную цель. Текущая настроенная цель проекта — origin/main; проверь её заново перед отправкой. Команда прошлого задания не разрешает автоматический push новых коммитов будущих задач.

Force push, переписывание истории, разрушительные reset/clean, удаление веток с работой и чужих изменений требуют отдельного разрешения. При неоднозначной цели или отказе сервера объясни причину, не обходи её опасной операцией.

## Контроль результата

После коммита проверь status и оставшиеся изменения. После push проверь совпадение отправленного HEAD с удалённой веткой. Чистая рабочая копия и синхронная ветка — разные вещи: ветка может совпадать с remote, а новые локальные файлы ещё не сохранены коммитом.
