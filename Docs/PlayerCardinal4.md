## Импорт и Animator

Существующий ApprovedHeroImporter расширен новым CardinalManifest: при наличии Assets/Art/PlayerCardinal4Manifest.json приоритетно импортирует только новый набор/восемь cardinal-клипов, старые ветки остаются резервом. Требует ровно4 Sprite для каждой комбинации. Настройки: Single Sprite/Full Rect/Custom pivot, Point, no mipmaps, Uncompressed, NPOT None/alpha из PNG/Clamp. Источники — Default Texture, не игровые кадры.

Обновляются те же Idle_Down/Left/Right/Up и Walk_Down/Left/Right/Up в Assets/Animations/Player64, с сохранением GUID. Samples16 сохраняется как сетка времени. Четыре рисунка Idle удерживаются по8 samples: фактическая смена2 FPS/цикл2 секунды; Walk по2 samples: смена8 FPS/цикл0,5 секунды. Это явное изменение темпа по новому запросу спокойного четырёхкадрового Idle; Samples16 не выдаётся за16 новых поз в секунду. Повтор первого кадра только замыкает петлю и не считается пятым рисунком. stopTime ровно2/0,5 секунды без добавочного интервала.

В двух существующих Blend Tree остаются только четыре cardinal child motion. Старые диагональные клипы не удаляются и не перезаписываются. PlayerController.useCardinalAnimations выбирает для Animator один ракурс по большей координате; при равной диагонали приоритет вертикали. Реальный moveInput/lastDirection/нормализованная диагональная скорость/FixedUpdate/WalkSpeed/gate остаются прежними. Сохранение последнего взгляда работает через прежние LastMoveX/Y. Самостоятельных новых контроллеров/менеджеров нет.

Сценовый метод WireActivePlayer должен через MCP назначить флаг и первый новый Idle_Down на существующем Player и сохранить SampleScene после проверки её состояния. BattleUnit/Inventory portrait по-прежнему используют прежние ссылки, боевой экран/профили/HP/MP/встреча не перерабатываются.
