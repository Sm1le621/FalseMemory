## Результат

Созданы **32 оригинальных PNG**, каждый действительно64×64: Skeleton Idle2/Move4/Attack3/Hurt2/Death4, Fire8, Heal8, Hit/Slash1. Кости/ржавая броня/бордовая ткань/меч/щит, пустые глазницы с двумя янтарными пикселями; враг обычный, не босс. Источники находятся в Assets/Art/Enemies/Skeleton64 и Assets/Art/VFX/{Fire64,Heal64,Hit64}. Фактический PNG-аудит: RGBA8, бинарная альфа0/255, максимум14 цветов в кадре, нет непрозрачных пикселей на краях. [Полная проверка каждого PNG](Verification/PixelVisualsAssets.json).

Встроенный imagegen использован для концептуального референса. Промпт: один обычный Dark Fantasy skeleton foot soldier, читаемый полный силуэт, ржавая броня/бордовая ткань/меч/щит, прозрачный фон, ограниченная палитра и требование64×64 без сглаживания. Генератор выдал крупный референс. Игровые кадры созданы отдельно непосредственно на целочисленной сетке64×64 в PixelBattleAssetBuilder; референс не масштабировался/не сэмплировался в игровой PNG. Эти растровые файлы/палитра/рецепт находятся в проекте. CLI/API fallback не использовался.

## Unity и анимации

Все новые изображения импортированы MCP: Sprite Single, Point, Uncompressed, no mipmaps, PPU100. В SampleScene существующий Enemy получил EnemySpriteAnimation и профиль Skeleton64; SpriteRenderer/battleSprite заменены на новый Idle-00. Позиция(21.06,-2.58,0), масштаб(2,2,1), Rigidbody/AI/Health/Encounter/два CircleCollider2D сохранены (тело radius0.32). Prefab скелета не обнаружен: старый Sprite использовали только эти две сцены. Старый PNG/его импорт не изменены/не удалены.

В BattleScene заменены previewEnemySprite/портрет, подключена impactSprite. BattlePresentation расширен кадрами Idle/Attack/Hurt/Death; герой сохраняет старое представление. Выбор кадра и исчезновение конечны и не владеют уроном. Magic/Items сохраняют число, но не включают старый прямоугольный glow, который закрывал pixel VFX; физическое попадание показывает Hit/Slash-mask, крит — прежний особый цвет/число/усиленную отдачу. Для MISS glow/реакция не применяются.

FireVisual/HealVisual содержат8 кадров, duration0.6, frameSize128 UI-единиц (двукратное отображение native64). Controller переиспользует один overlay с кадрами и прежний пул до24 частиц. Смена/отключение/выгрузка очищает визуал, пустой профиль/кадры безопасны. Боевые расчёты, урон, MP, предметы, награды и очередь не перенесены в анимации. Обе сцены фактически сохранены через MCP.
